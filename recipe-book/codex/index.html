How the recipe works

  1. Choose the ingredients

    Research + curated data

    → Architecture and training corpus
    How this works

    Choose a model design, prepare examples and encode them for training. The egg and grain jar show the two starting inputs.

  2. Build the kitchen

    Funding + infrastructure

    → Usable training hardware
    How this works

    Buy or rent computing capacity and arrange networking, power and cooling. Capital enables the kitchen; a training run consumes its capacity.

  3. Cook the base

    Data + compute + optimization

    → A pretrained model
    How this works

    Run the training algorithm over the prepared data. Repeated parameter updates produce a base model that can predict or complete inputs.

  4. Season for the task

    Demonstrations + feedback

    → A refined model, when applicable
    How this works

    Some teams continue training for instruction following or preferred behavior. A base model can also be released before this stage.

  5. Taste and check

    Defined tasks + scoring

    → Evidence of capabilities and failures
    How this works

    Test the model, record conditions and look for weaknesses. Evaluation can happen throughout development and lead back to another training iteration.

  6. Serve a response

    Trained model + new prompt

    → Generated output
    How this works

    Deploy the model and run inference for a new request. Using the model still requires compute, even though its initial training is finished.

Teams can revisit earlier steps. Post-training is optional.
